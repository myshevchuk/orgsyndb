## MODIFIED Requirements

### Requirement: Collection layout
A collection SHALL be a directory holding a file `orgsyndb.toml`. Relative to that directory:
- `org/procedures/` holds Org procedure sources and `md/procedures/` Markdown procedure sources. Either may be missing, which means it is empty.
- `md/sequences/` holds the synthesis sequences (synthesis-sequences "Sequence files"). It may be missing, which means it is empty.
- `static/`, when present, is copied into the site root; procedure scheme images live in `static/structures/` (procedure-schema "Scheme image"). Structure images come from the registry (compound-registry "Structure images").

The collection holds no compounds and no vocabularies: they are its registry's (compound-registry "Registry source").
- `build/`, `public/` and `pdf/` are generated by the program and are the only paths of the collection it writes, apart from the files `new` and `init` create.

`orgsyndb.toml` is the collection's settings file. It SHALL parse as TOML into a table holding the key `format`, with the integer value `1`, and optionally `registry`, a non-empty string naming the collection's registry (compound-registry "Registry source"), and `fields`, the collection's procedure field declarations (procedure-fields "Procedure field declarations"), and no other key. A file that cannot be read as TOML, a missing or other `format`, a `registry` that is not a non-empty string, or another key is an error: the program prints `orgsyndb: error: <collection>/orgsyndb.toml: <reason>` and exits 1 before any step. The program checks `fields` no further; the validator does (procedure-fields "Procedure declaration errors are configuration errors").

#### Scenario: Unknown format
- **WHEN** a test runs `tools/orgsyndb -C <dir> validate` on a directory whose `orgsyndb.toml` is `format = 2`
- **THEN** it exits 1, stderr contains `orgsyndb.toml` and `format`, and `<dir>/build/` was not created

#### Scenario: Unknown key
- **WHEN** a test runs `tools/orgsyndb -C <dir> validate` on a directory whose `orgsyndb.toml` holds `format = 1` and `title = "X"`
- **THEN** it exits 1, and stderr contains `title`

#### Scenario: Declarations do not stop other subcommands
- **WHEN** a test runs `tools/orgsyndb -C <dir> clean` on a directory whose `orgsyndb.toml` holds `format = 1` and a `[[fields.procedure]]` table with only `key = "notebook"`
- **THEN** it exits 0

#### Scenario: A registry that is not text
- **WHEN** a test runs `tools/orgsyndb -C <dir> validate` on a directory whose `orgsyndb.toml` holds `format = 1` and `registry = 3`
- **THEN** it exits 1, and stderr contains `orgsyndb.toml` and `registry`
