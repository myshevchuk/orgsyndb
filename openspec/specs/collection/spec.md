# collection Specification

## Purpose
Define a collection, the directory of procedures that the application builds: its `orgsyndb.toml` marker and layout, how the program chooses it, which generated files go into it, and `init`.
## Requirements
### Requirement: Collection layout
A collection SHALL be a directory holding a file `orgsyndb.toml`. Relative to that directory:
- `org/procedures/` holds Org procedure sources and `md/procedures/` Markdown procedure sources. Either may be missing, which means it is empty.
- `compounds/` holds the compound registry, one `<key>.toml` file per compound (compound-registry "Compound files"). It may be missing, which means it is empty.
- `static/`, when present, is copied into the site root; structure images live in `static/structures/`.
- `build/`, `public/` and `pdf/` are generated by the program and are the only paths of the collection it writes, apart from the files `new` and `init` create.

`orgsyndb.toml` SHALL parse as TOML into a table whose only key is `format`, with the integer value `1`. Any other content is an error: the program prints `orgsyndb: error: <collection>/orgsyndb.toml: <reason>` and exits 1 before any step.

#### Scenario: Unknown format
- **WHEN** a test runs `tools/orgsyndb -C <dir> validate` on a directory whose `orgsyndb.toml` is `format = 2`
- **THEN** it exits 1, stderr contains `orgsyndb.toml` and `format`, and `<dir>/build/` was not created

#### Scenario: Unknown key
- **WHEN** a test runs `tools/orgsyndb -C <dir> validate` on a directory whose `orgsyndb.toml` holds `format = 1` and `title = "X"`
- **THEN** it exits 1, and stderr contains `title`

### Requirement: Choosing the collection
The program SHALL accept a global option `-C DIR` or `--collection DIR` (also `--collection=DIR`) before the subcommand.
- With the option, `DIR` is the collection. When `DIR/orgsyndb.toml` does not exist, the program exits 1 with an error naming `DIR` and `orgsyndb.toml`; it does not search elsewhere.
- Without it, the collection is the first directory holding `orgsyndb.toml` among the working directory and its ancestors. When there is none, the program exits 1 with an error that names `-C` and `init`.

Only `export`, `validate`, `build`, `serve`, `pdf`, `new` and `clean` use a collection. `help`, `check-deps` and `init` never look for one.

#### Scenario: Found from a subdirectory
- **WHEN** a test runs `<app>/tools/orgsyndb validate` with the working directory set to `md/procedures/` of a collection copy
- **THEN** it exits 0, and the collection copy's `build/export/` exists afterwards

#### Scenario: No collection found
- **WHEN** a test runs `tools/orgsyndb build` in an empty temporary directory outside any collection
- **THEN** it exits 1, stderr contains `-C` and `init`, and the directory is still empty

#### Scenario: Option names a directory without a marker
- **WHEN** a test runs `tools/orgsyndb -C <empty temporary directory> build`
- **THEN** it exits 1, stderr contains `orgsyndb.toml`, and the directory is still empty

### Requirement: Generated files stay in the collection
A run SHALL write generated files only under the collection's `build/`, `public/` and `pdf/`, and under the application's `.emacs-batch/` and `.tools/`. In particular Hugo's resource cache is `<collection>/build/hugo-resources/` and Hugo runs without a build lock, so nothing is written under the application's `site/`.

#### Scenario: The application's site directory is untouched
- **WHEN** an integration test snapshots the application copy's `site/`, runs `tools/orgsyndb -C <collection> build`, and snapshots it again
- **THEN** the build exits 0, the snapshots are equal, and neither `site/.hugo_build.lock` nor `site/resources/` exists

### Requirement: init subcommand
`tools/orgsyndb init DIR` SHALL create an empty collection in `DIR`, creating `DIR` and its parents when missing. It writes:
- `orgsyndb.toml` holding `format = 1`, preceded by comment lines;
- `.gitignore` holding exactly the lines `/build/`, `/public/` and `/pdf/`, or, when a `.gitignore` exists, those of these lines it lacks, appended;
- the empty directories `org/procedures/`, `md/procedures/`, `compounds/` and `static/structures/`.

It writes `orgsyndb.toml` last, so that an interrupted `init` can be rerun. It exits 1 without writing anything when `DIR/orgsyndb.toml` already exists, and 2 when `DIR` is missing from the command line. It prints the collection's absolute path. It does not run `git` and does not configure a hook.

#### Scenario: New collection takes a procedure
- **WHEN** a test runs `tools/orgsyndb init "<tmp>/new collection"`, then `tools/orgsyndb -C "<tmp>/new collection" new --md "Ethyl acetate"`
- **THEN** both exit 0, the second creates `md/procedures/OSDB-0001-ethyl-acetate.md`, and `orgsyndb.toml` parses with `tomllib` to `{"format": 1}`

#### Scenario: Existing .gitignore is kept
- **WHEN** a test runs `tools/orgsyndb init <dir>` on a directory whose `.gitignore` is `*.swp` and `/public/` without a final newline
- **THEN** it exits 0, and the `.gitignore` is `*.swp`, `/public/`, `/build/` and `/pdf/`, one per line

#### Scenario: Existing collection is refused
- **WHEN** a test runs `tools/orgsyndb init <dir>` twice on the same directory
- **THEN** the second run exits 1, and every file written by the first run is unchanged

#### Scenario: The demo collection matches init
- **WHEN** a test compares `examples/demo/.gitignore` and `examples/demo/orgsyndb.toml` with the files `init` writes
- **THEN** both `.gitignore` files are equal, and both `orgsyndb.toml` files parse to `{"format": 1}`
